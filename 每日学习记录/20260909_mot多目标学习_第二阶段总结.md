# 二、Track 生命周期管理

之前的 `Track` 对象主要保存：

```text
id
bbox
age
```

本阶段增加：

```text
missed
```

用于记录一个目标连续多少帧没有被检测到。

例如：

```text
Frame 1    ID 1
Frame 2    ID 1
Frame 3    未检测到
Frame 4    未检测到
```

此时可以：

```text
missed = 2
```

真正的追踪器通常还会设置：

```text
max_age
```

当：

```text
missed > max_age
```

时，将该轨迹删除。

这解决了之前 SimpleTracker 中：

> 已经离开画面的目标永远保留在 tracks 中

的问题。

# 三、理解 Kalman Filter

## 1. 为什么 MOT 需要卡尔曼滤波？

SimpleTracker 只能依赖当前检测框与上一帧检测框之间的 IoU。

如果目标移动较快，或者暂时被遮挡：

```text
上一帧有检测
↓
下一帧检测失败
```

SimpleTracker 就不知道目标在哪里。

SORT 使用 Kalman Filter：

```text
历史运动状态
↓
预测下一帧位置
```

即使 YOLO 暂时没有检测到目标，也可以对目标位置进行短时间预测。

---

# 四、Kalman Filter 的基本状态

本阶段为了方便理解，使用简化状态：

```text
[cx, cy, vx, vy]
```

其中：

```text
cx = 目标中心点 x
cy = 目标中心点 y

vx = x 方向速度
vy = y 方向速度
```

YOLO 提供的是检测结果：

```text
bbox
```

转换为中心点：

```text
cx = (x1 + x2) / 2
cy = (y1 + y2) / 2
```

# 五、Kalman Filter 两个核心操作

## predict()

```python
predict()
```

作用：

> 根据当前运动状态预测目标下一帧在哪里。

例如：

```text
Frame 1 x = 100
Frame 2 x = 110
Frame 3 x = 120
```

理论上可以逐渐预测：

```text
Frame 4 x ≈ 130
```

---

## update()

```python
update()
```

或者 OpenCV 中的：

```python
correct()
```

作用：

> 使用 YOLO 当前帧的实际检测结果修正 Kalman 的预测。

因此卡尔曼滤波不断进行：

```text
Predict
↓
获得实际检测
↓
Correct / Update
↓
Predict
↓
Correct
```

# 七、Kalman Filter 测试结果

测试目标持续向右移动：

```text
检测位置：

110
120
130
140
```

实际运行得到预测：

```text
Frame 1
预测 x1 = 100.00

Frame 2
预测 x1 ≈ 100.29

Frame 3
预测 x1 ≈ 102.45

Frame 4
预测 x1 ≈ 110.02
```

说明：

Kalman Filter 一开始不知道目标的运动速度，因为初始化：

```text
vx = 0
vy = 0
```

随着不断接收到检测结果：

```text
110 → 120 → 130 → 140
```

它逐渐发现：

> 目标正在向右移动。

因此预测位置开始持续向右移动。

这一实验帮助理解：

> Kalman Filter 不是一个提前训练好的神经网络，而是在追踪过程中不断预测和修正目标运动状态。

# 八、为什么还需要匈牙利算法？

之前 SimpleTracker 使用：

```text
每个 Detection
↓
寻找最大 IoU Track
```

这种方法属于：

```text
Greedy Matching
贪心匹配
```

问题是：

> 每个目标单独选择当前最优匹配，并不一定能够得到所有目标的全局最佳匹配。

---

# 九、Hungarian Algorithm

匈牙利算法解决：

> 多个 Track 与多个 Detection 之间的一一最优分配问题。

例如：

```text
           Detection 1    Detection 2

Track 1        IoU             IoU

Track 2        IoU             IoU
```

首先建立：

```text
IoU Matrix
```

然后通过 Hungarian Algorithm 找到最佳匹配组合。

---

# 十、IoU Matrix

例如：

```text
          D1      D2

T1       0.8     0.7

T2       0.75    0.1
```

代表每一个：

```text
Track
```

与每一个：

```text
Detection
```

之间的 IoU。

---

# 十一、为什么使用 cost = 1 - IoU？

IoU：

```text
越大越好
```

但 `linear_sum_assignment` 求解的是：

```text
最小代价
```

因此转换：

```text
cost = 1 - IoU
```

例如：

```text
IoU = 0.9
↓
cost = 0.1
```

而：

```text
IoU = 0.2
↓
cost = 0.8
```

这样：

```text
最小 cost
```

就等价于：

```text
最大 IoU
```

---
